WHY REDIS TIMESERIES

Built for operational applications

01
Low-latency reads

Applications read live and historical values from an in-memory serving layer instead of repeatedly loading the PI historian.

02
Compressed storage

Time-series samples use compressed chunks by default, reducing memory consumption and memory accesses for typical telemetry.

03
Query flexibility

Range filters, value filters, on-demand aggregation, label queries, GROUPBY and reducers are available as native commands.

04
Automatic rollups

Pre-computed minute, hour or day series accelerate long-range dashboards without separate cron jobs or ETL pipelines.

05
Protect the OT system

Dashboards, alerting services and AI applications scale independently while PI remains the authoritative historian.
